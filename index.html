Sentinel Flux Core: Modular SAR Response Toolkit

A reproducible Python toolkit that maps floods from Sentinel-1 radar imagery and reports their likely impact, built as decision support for relief teams and benchmarked on the Pakistan 2022 floods.

Problem

During Pakistan's monsoon floods, cloud cover blocks optical satellite imagery exactly when relief teams need it. Published reference flood products cover different footprints, and raw pixel maps are not tied to evidence a decision-maker can act on. Flood mapping is therefore slow and uncertain.

Approach

Sentinel-1 scenes (VV/VH) are discovered through the Copernicus Data Space STAC/OData APIs and described in event YAML manifests that carry full provenance: orbit, processor, DEM, CRS and resolution. The detector combines temporal change evidence with optional terrain penalties, permanent-water exclusion and connected-component clean-up; transparent physics baselines stay selectable for comparison. A scikit-learn feature classifier is trained under event holdout and writes flood-probability rasters. Evaluation compares products with Copernicus GFM and CEMS reference masks, holding out whole flood events rather than random tiles so that real generalisation failures become visible. An impact module overlays built-up area, transport, facilities and land use, and a Streamlit/Leafmap dashboard supports human review before any message is approved.

My part

Team coordinator and documentation lead. I authored the complete technical documentation (requirements, use-case analysis, design, methodology and evaluation; 81 pages) and designed the Typer/Rich command-line interface that drives the ingestion, validation, detection, benchmarking, calibration, impact-report and dashboard workflows.

Limits

The validated path is observational flood mapping, not prediction. Forecasting, data-fusion and severity modules exist in the code base but remain experimental and are kept separate from the operational evidence. Measured accuracy depends on reference quality, SAR preprocessing, valid-mask footprints and how representative the areas of interest are. The system is designed as uncertainty-aware, human-reviewed decision support rather than an automated warning system.

Operational workflow driven by the sarcd command-line interface

  1. sarcd doctorChecks Python 3.10+, rasterio, SNAP GPT, credentials and the data root.
  2. sarcd validate-data --event EVENT.yamlValidates the event manifest: paths, CRS, transform, nodata, dates, masks.
  3. sarcd detect-flood --event EVENT.yamlWrites probability, binary mask and uncertainty rasters.
  4. sarcd benchmark-suite --events SUITE.yamlMulti-event benchmark: F1, IoU, AP, ROC-AUC, Brier, ECE; gate on held-out macro F1.
  5. sarcd fit-probability-calibrationFits the calibration mapping; reports Brier score, ECE and reliability bins.
  6. sarcd impact-reportIntersects flood masks with exposure layers: built-up area, transport, facilities and land use.
  7. sarcd dashboard-manifestBuilds the dashboard manifest from real outputs for analyst review in Streamlit + Leafmap.
